Function Notation and Evaluation

Intuition

In Relations and Functions you saw that a function is more than a formula: it is a domain, a rule, and a codomain, all three together. That lesson also showed that the same curve can be a function of one variable but not another. You also already know how to drop a number into f(x)f(x)f(x) and read off the answer. This lesson is about the notation f(x)f(x)f(x) itself, and it makes one move that runs through the rest of the chapter. The letter inside the parentheses is not really the variable xxx. That letter is a slot, and any expression the function accepts can go in it: a number, another variable, or a whole expression like x+hx + hx+h. Once the slot can hold an expression, three things become possible that a bare yyy could never express. Those three are writing f(2x)f(2x)f(2x) and f(x+h)f(x + h)f(x+h), asking whether f(a+b)f(a + b)f(a+b) equals f(a)+f(b)f(a) + f(b)f(a)+f(b), and building the difference quotient that measures how fast fff changes. We take fff apart until the notation is doing real work.

Learning goals

  • Read fff as the function and f(x)f(x)f(x) as one value
  • Copy any expression into every slot the argument marks
  • Reject f(a+b)=f(a)+f(b)f(a + b) = f(a) + f(b)f(a+b)=f(a)+f(b) as a general rule
  • Simplify a difference quotient and read it as a secant slope
  • Require matching domains, codomains, and outputs before calling two functions equal
  • Evaluate a piecewise rule by choosing the right case

The function is fff; its value is f(x)f(x)f(x)

Start by separating two things that the phrase “the function f(x)=x2f(x) = x^2f(x)=x2” quietly runs together. Strictly, fff is the function, its domain, rule, and codomain together, as in Relations and Functions, while f(x)f(x)f(x) is a number: the output the rule produces at the input xxx. For f(x)=x2f(x) = x^2f(x)=x2, the output at input 333 is f(3)=9f(3) = 9f(3)=9, one specific number, not the function itself. Writing “the function f(x)f(x)f(x)” is a mild abuse of language that everyone uses. But when a step gets subtle, it pays to remember that fff is the machine, domain and codomain included, and f(x)f(x)f(x) is what comes out of it.

This also settles what the parentheses are not. They are not multiplication. f(x)f(x)f(x) does not mean fff times xxx, and f(3)f(3)f(3) is not 3f3f3f; fff is a rule, not a number, so there is nothing to multiply it by. The parentheses do one job only: they hold the input the rule is about to act on. Keep that job in mind, because the next section widens what is allowed to sit inside them.

The argument is a slot, not the letter xxx

Picture the rule with an empty box where the input goes:

f( □ )=□2+1.f(\,\square\,) = \square^2 + 1.f(□)=□2+1.

The box says “whatever you feed me gets squared, then 111 is added.” The xxx in f(x)=x2+1f(x) = x^2 + 1f(x)=x2+1 is just a name written in that box so we can talk about a general input; it is a placeholder, not a special number. f(3)=32+1,f(−x)=(−x)2+1,f(2x)=(2x)2+1,f(a)=a2+1.\begin{aligned} f(3) &= 3^2 + 1, &\qquad f(-x) &= (-x)^2 + 1, \\ f(2x) &= (2x)^2 + 1, &\qquad f(a) &= a^2 + 1. \end{aligned}f(3)f(2x)​=32+1,=(2x)2+1,​f(−x)f(a)​=(−x)2+1,=a2+1.​

and you may drop a function value into the slot too: f(f(x))=(f(x))2+1=(x2+1)2+1f(f(x)) = (f(x))^2 + 1 = (x^2 + 1)^2 + 1f(f(x))=(f(x))2+1=(x2+1)2+1, treating f(x)f(x)f(x) as just another expression. Combining functions this way earns its own lesson later in the chapter; here it is nothing more than substitution.

Because the slot only cares about what you put in, not what you call it, the name of the input variable carries no meaning. The rules f(x)=x2+1f(x) = x^2 + 1f(x)=x2+1 and f(t)=t2+1f(t) = t^2 + 1f(t)=t2+1 have the same domain, the same codomain, and pair every input with the same output. So by the equality test later in this lesson, those two rules are the same function. Renaming xxx to ttt changes the writing, not the function.

The slot also reads backward. Because f(x)f(x)f(x) is a number, an equation like f(x)=7f(x) = 7f(x)=7 is an ordinary equation in xxx, and solving it uses only the equation-solving skills from Chapter 1. For f(x)=x2+1f(x) = x^2 + 1f(x)=x2+1, solving f(x)=17f(x) = 17f(x)=17 means solving x2+1=17x^2 + 1 = 17x2+1=17, so x2=16x^2 = 16x2=16 and x=±4x = \pm 4x=±4: both inputs produce the output 171717.

The one habit the slot demands is substitution with parentheses. Wrap the whole input before applying the rule. Skip the wrapping and you silently change the problem: for f(x)=x2f(x) = x^2f(x)=x2,

f(−x)=(−x)2=x2,not−x2.f(-x) = (-x)^2 = x^2, \qquad \text{not} \qquad -x^2.f(−x)=(−x)2=x2,not−x2.

The correct result squares the input; the careless −x2-x^2−x2 negates a square, and the two disagree at every nonzero input (at x=3x = 3x=3, (−3)2=9(-3)^2 = 9(−3)2=9 but −32=−9-3^2 = -9−32=−9). The parentheses are what hold the whole expression together inside the slot.

One family of rules does respect both moves: the straight-line rules through the origin, f(x)=mxf(x) = mxf(x)=mx.

The rules f(x)=mxf(x) = mxf(x)=mx add and scale, and scaling alone pins them down#

Take any rule of the form f(x)=mxf(x) = mxf(x)=mx with mmm a constant. For all inputs aaa and bbb, the distributive law gives

f(a+b)=m(a+b)=ma+mb=f(a)+f(b),f(a + b) = m(a + b) = ma + mb = f(a) + f(b),f(a+b)=m(a+b)=ma+mb=f(a)+f(b),

so the output of a sum is the sum of the outputs. For any constant kkk,

f(kx)=m(kx)=k(mx)=k f(x),f(kx) = m(kx) = k(mx) = k\,f(x),f(kx)=m(kx)=k(mx)=kf(x),

so scaling the input by kkk scales the output by kkk. Both identities hold for every rule f(x)=mxf(x) = mxf(x)=mx.

The reverse direction holds too, and it is the scaling identity that delivers it. Suppose f(kx)=k f(x)f(kx) = k\,f(x)f(kx)=kf(x) for every real kkk and every xxx. Put x=1x = 1x=1: then f(k)=k f(1)f(k) = k\,f(1)f(k)=kf(1) for all kkk, which is exactly f(x)=f(1) xf(x) = f(1)\,xf(x)=f(1)x, a rule of the form mxmxmx with slope m=f(1)m = f(1)m=f(1). So the pair of identities does pin down the through-origin lines, with no extra assumption needed. Additivity by itself is weaker: the identity f(a+b)=f(a)+f(b)f(a + b) = f(a) + f(b)f(a+b)=f(a)+f(b) alone does not force f(x)=mxf(x) = mxf(x)=mx without a further hypothesis such as the graph having no breaks. Notice as well that adding a nonzero constant already destroys additivity: for f(x)=mx+cf(x) = mx + cf(x)=mx+c,

f(a)+f(b)=ma+mb+2c,f(a+b)=ma+mb+c,f(a) + f(b) = ma + mb + 2c, \qquad f(a + b) = ma + mb + c,f(a)+f(b)=ma+mb+2c,f(a+b)=ma+mb+c,

and these agree only when c=0c = 0c=0. Even the lines that everyday language calls linear are additive only when they pass through the origin.

∎

So the rules f(x)=mxf(x) = mxf(x)=mx are exactly the rules that respect scaling, and each of them is additive as well. The one caution is that additivity on its own is weaker: it does not single out f(x)=mxf(x) = mxf(x)=mx without an added assumption. That gap is why the scaling identity is the one that pins the rules down.

The difference quotient

Now that f(x+h)f(x + h)f(x+h) is expressible, we can measure how much fff changes as the input moves from xxx to x+hx + hx+h, as long as both xxx and x+hx + hx+h are inputs fff actually accepts. The change in output is f(x+h)−f(x)f(x + h) - f(x)f(x+h)−f(x), and dividing by the change in input hhh gives the difference quotient

f(x+h)−f(x)h.\frac{f(x + h) - f(x)}{h}.hf(x+h)−f(x)​.

Work it out for f(x)=x2f(x) = x^2f(x)=x2. The numerator expands and the x2x^2x2 terms cancel:

f(x+h)−f(x)=(x+h)2−x2=(x2+2xh+h2)−x2=2xh+h2.f(x + h) - f(x) = (x + h)^2 - x^2 = (x^2 + 2xh + h^2) - x^2 = 2xh + h^2.f(x+h)−f(x)=(x+h)2−x2=(x2+2xh+h2)−x2=2xh+h2.

Every term left has a factor of hhh, so divide:

2xh+h2h=h(2x+h)h=2x+h,h≠0.\frac{2xh + h^2}{h} = \frac{h(2x + h)}{h} = 2x + h, \qquad h \ne 0.h2xh+h2​=hh(2x+h)​=2x+h,h=0.

Hold on to that restriction h≠0h \ne 0h=0, because it is the whole point. Cancelling the hhh is a division, and you can only divide by hhh when h≠0h \ne 0h=0. The original difference quotient 2xh+h2h\frac{2xh + h^2}{h}h2xh+h2​ is undefined at h=0h = 0h=0, where it reads 0/00/00/0, while the simplified 2x+h2x + h2x+h is perfectly happy at h=0h = 0h=0. The two expressions agree for every h≠0h \ne 0h=0 but have different domains, so they are genuinely different expressions that happen to match wherever both are defined. This is exactly the effect you met in Chapter 1, where clearing a denominator could change which inputs are allowed. Here cancelling an hhh does the same thing, and the next section names why it matters.

The quantity itself has a meaning worth naming. The points (x,f(x))(x, f(x))(x,f(x)) and (x+h,f(x+h))(x + h, f(x + h))(x+h,f(x+h)) sit on the graph of fff, and f(x+h)−f(x)h\frac{f(x + h) - f(x)}{h}hf(x+h)−f(x)​ is the slope of the straight line through them, the secant line. It is the average rate of change of fff between the two inputs. A later course lets hhh shrink toward 000 to turn this secant slope into the slope of the curve at a single point, but that is calculus. Here we go only as far as the algebra, and the algebra is exactly the careful substitution of this lesson.

When are two functions equal?

The difference quotient just handed us two expressions that agree everywhere they are both defined yet are not the same, because their domains differ. That is a clue about what equality of functions should mean, and it deserves a precise statement.

Two functions are equal exactly when their domains, codomains, and values all match#

Recall from Relations and Functions that a function is a set of input-output pairs, with no repeated first coordinate, together with a declared codomain. We prove that fff and ggg are the same function if and only if three conditions all hold. The three are: the same domain, the same codomain, and f(x)=g(x)f(x) = g(x)f(x)=g(x) at every input xxx in that domain.

Suppose first that fff and ggg are the same function. Then they are literally the same set of pairs and the same codomain. The domain of a function is the set of its first coordinates, so the two domains match. For each input xxx the one pair with first coordinate xxx is shared by both sets, so f(x)=g(x)f(x) = g(x)f(x)=g(x) at every xxx. Equal functions therefore agree on domain, codomain, and every value.

Conversely, suppose fff and ggg have the same domain DDD, the same codomain, and f(x)=g(x)f(x) = g(x)f(x)=g(x) for every xxx in DDD. Then for each xxx in DDD the pair (x,f(x))(x, f(x))(x,f(x)) is the pair (x,g(x))(x, g(x))(x,g(x)), so the two sets of pairs are identical, and the codomains match by assumption. Having the same pairs and the same codomain, fff and ggg are the same function.

Both directions hold, so the equality of two functions is precisely the equality of their domains, their codomains, and all their values, no more and no less.

∎

This is why f(x)=x2xf(x) = \dfrac{x^2}{x}f(x)=xx2​ and g(x)=xg(x) = xg(x)=x are different functions, not equal ones. For x≠0x \ne 0x=0 the fraction cancels, x2x=x\dfrac{x^2}{x} = xxx2​=x, so the two rules agree wherever both are defined. But x=0x = 0x=0 lies in ggg‘s domain and not in fff‘s, since x2x\dfrac{x^2}{x}xx2​ reads 0/00/00/0 there. Their domains differ, so by the test above they are not the same function. It is the same lesson the difference quotient taught: 2x+h2x + h2x+h and 2xh+h2h\dfrac{2xh + h^2}{h}h2xh+h2​ agree for h≠0h \ne 0h=0 but part ways at h=0h = 0h=0, and matching values on the overlap is not enough. This is also why every cancelling step in Chapter 1 had to record the inputs it removed.

Piecewise definitions

A piecewise definition gives a single function by splitting the input into cases and naming a rule on each. For example,

f(x)={x2if x<02x+1if x≥0f(x) = \begin{cases} x^2 & \text{if } x < 0 \\ 2x + 1 & \text{if } x \ge 0 \end{cases}f(x)={x22x+1​if x<0if x≥0​

is one function, not two. To evaluate it, first find which case the input falls in, then use that case’s rule. Since −3<0-3 < 0−3<0, use the top rule: f(−3)=(−3)2=9f(-3) = (-3)^2 = 9f(−3)=(−3)2=9. Since 4≥04 \ge 04≥0, use the bottom rule: f(4)=2(4)+1=9f(4) = 2(4) + 1 = 9f(4)=2(4)+1=9. The boundary input x=0x = 0x=0 is caught by the second case, because 0≥00 \ge 00≥0 is true while 0<00 < 00<0 is false, so f(0)=2(0)+1=1f(0) = 2(0) + 1 = 1f(0)=2(0)+1=1.

For a piecewise rule to define a function at all, the cases must do two things: cover the whole domain, and never assign one input two different outputs. If some input were left out of every case, it would get no output. And if two cases overlapped and disagreed on the overlap, that input would be handed two different outputs, which Relations and Functions forbids. Cases are allowed to overlap when they agree there. For instance ∣x∣\lvert x \rvert∣x∣ can be written as xxx for x≥0x \ge 0x≥0 and −x-x−x for x≤0x \le 0x≤0, which overlap at 000 yet agree, since both give 000. The easy way to rule out any conflict is to make the cases disjoint, which is what this example does. Here x<0x < 0x<0 and x≥0x \ge 0x≥0 share no input and together cover every real number, so fff is well defined.

Common mistakes

Common mistakes

  • Reading f(x)f(x)f(x) as multiplication. fff is a rule, not a number, so f(x)f(x)f(x) means “apply fff to xxx,” never ”fff times xxx.” There is nothing to multiply, and f(3)f(3)f(3) is not 3f3f3f.
  • Dropping the parentheses when substituting. For f(x)=x2f(x) = x^2f(x)=x2, the value f(−x)f(-x)f(−x) is (−x)2=x2(-x)^2 = x^2(−x)2=x2, not −x2-x^2−x2. Wrap the whole input before applying the rule, or the sign or a coefficient goes wrong.
  • Distributing fff across a sum. In general f(a+b)≠f(a)+f(b)f(a + b) \ne f(a) + f(b)f(a+b)=f(a)+f(b) and f(2x)≠2f(x)f(2x) \ne 2f(x)f(2x)=2f(x). Only the through-origin rules f(x)=mxf(x) = mxf(x)=mx are additive and scale, and even f(x)=mx+cf(x) = mx + cf(x)=mx+c with c≠0c \ne 0c=0 fails.
  • Forgetting the h≠0h \ne 0h=0 restriction. The difference quotient simplifies only after you divide by hhh, which needs h≠0h \ne 0h=0. The simplified form and the original agree just where both are defined, not at h=0h = 0h=0.
  • Calling two functions equal because the formulas match after cancelling. x2x\dfrac{x^2}{x}xx2​ and xxx agree for x≠0x \ne 0x=0 but differ at 000, so they are different functions. Equality needs the same domain, not only the same simplified rule.
  • Leaving a gap or a conflict in piecewise cases. The cases must cover the whole domain and must never give one input two different outputs. Overlap is fine when the rules agree there; making the cases disjoint is just the easy way to guarantee no conflict.

Key takeaways

  • fff names the function (its domain, rule, and codomain together); f(x)f(x)f(x) is the single output value at the input xxx. The parentheses mark the input, not a product.
  • The argument is a slot: f(2x)f(2x)f(2x), f(x+h)f(x + h)f(x+h), f(−x)f(-x)f(−x), and f(a)f(a)f(a) all mean copy the whole expression into every xxx. The name of the input variable does not matter, so f(t)=t2+1f(t) = t^2 + 1f(t)=t2+1 and f(x)=x2+1f(x) = x^2 + 1f(x)=x2+1 define the same function.
  • In general f(a+b)≠f(a)+f(b)f(a + b) \ne f(a) + f(b)f(a+b)=f(a)+f(b) and f(2x)≠2f(x)f(2x) \ne 2f(x)f(2x)=2f(x). The rules f(x)=mxf(x) = mxf(x)=mx both add and scale, and the scaling identity f(kx)=k f(x)f(kx) = k\,f(x)f(kx)=kf(x) characterizes them (set x=1x = 1x=1 to get f(x)=f(1) xf(x) = f(1)\,xf(x)=f(1)x); additivity by itself is weaker and does not.
  • The difference quotient f(x+h)−f(x)h\dfrac{f(x + h) - f(x)}{h}hf(x+h)−f(x)​ simplifies for h≠0h \ne 0h=0 to the slope of the secant line through (x,f(x))(x, f(x))(x,f(x)) and (x+h,f(x+h))(x + h, f(x + h))(x+h,f(x+h)), the average rate of change of fff from xxx to x+hx + hx+h.
  • Two functions are equal exactly when they share a domain, a codomain, and every value. So x2x\dfrac{x^2}{x}xx2​ and xxx are different functions, because 000 is in one domain and not the other.
  • A piecewise rule is one function given by cases. Evaluate it by choosing the case the input falls in, and make sure the cases cover the domain and never give one input two different outputs.

A bit of history (optional)

A rule once had no name of its own. To say what squaring does to some other quantity, you wrote the whole formula out again with the new quantity in place of the old. There was nothing shorter to write, because no symbol stood for the rule apart from its ingredients.

Leonhard Euler, a Swiss mathematician, supplied one in 1734. He wrote fff for the rule and put its input in parentheses after it, giving the f(x)f(x)f(x) you have used all lesson. The notation does two jobs at once, and both deserve naming. It gives the rule a name that survives when the input changes. And it marks the input as a position, a slot standing ready for whatever you care to drop into it.

The second job is the one that pays here. Once the slot is a position rather than a particular letter, you may fill it with a number, with another letter, or with a whole expression. Nothing about fff has to be rewritten to accommodate any of them.

Euler was not saving anyone ink. Naming the rule fff made it easy to ask what the same rule does at a nearby input, the question written today as f(x+h)f(x + h)f(x+h). Comparing that value to f(x)f(x)f(x) is what the difference quotient at the center of this lesson does.
