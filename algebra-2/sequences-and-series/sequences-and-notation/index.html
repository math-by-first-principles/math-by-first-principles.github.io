Sequences and Notation

Intuition

A function takes an input, applies a rule, and returns exactly one output. Feed a function nothing but the counting numbers 1,2,3,4,…1, 2, 3, 4, \ldots1,2,3,4,…, and write its outputs in that order: 2,5,10,17,26,…2, 5, 10, 17, 26, \ldots2,5,10,17,26,… That list is a sequence. It is not a new kind of object. It is a function whose domain has been cut down to consecutive integers. Everything else in this lesson (terms, indices, recursion, sigma notation) builds on that one idea.

Learning goals

  • Define a sequence as a function on consecutive integers, finite or infinite
  • Separate the index from the term it names
  • Contrast an explicit rule with a recursive one
  • Supply enough seeds for a recursion that looks back kkk steps
  • Read ∑k=mpak\sum_{k=m}^{p} a_k∑k=mp​ak​ with both limits included
  • Treat the summation index as a dummy name

A sequence is a function on consecutive integers

Definition. A sequence is a function whose domain is a run of consecutive integers, starting from some stated place and continuing upward, either forever, which makes an infinite sequence, or until it has exactly kkk terms, which makes a finite sequence. Unless a lesson says otherwise, that starting place is 111, so the default domain is {1,2,3,…}\{1, 2, 3, \ldots\}{1,2,3,…} (infinite) or {1,2,…,k}\{1, 2, \ldots, k\}{1,2,…,k} (finite, with kkk terms). Some sequences are more natural indexed from 000 instead, with domain {0,1,2,…}\{0, 1, 2, \ldots\}{0,1,2,…} or {0,1,…,k−1}\{0, 1, \ldots, k-1\}{0,1,…,k−1} for the same kkk terms; the idea is unchanged, because the inputs are still consecutive integers running upward from wherever the lesson says to start. If the function is named aaa, we write its output at the input nnn as ana_nan​ rather than a(n)a(n)a(n), and we call ana_nan​ the term of the sequence at index nnn.

The only genuinely new thing in that definition is the subscript. Where you used to write f(3)f(3)f(3) you now write a3a_3a3​, and where you used to write f(n)=n2+1f(n) = n^2 + 1f(n)=n2+1 you now write an=n2+1a_n = n^2 + 1an​=n2+1. The parentheses became a subscript and nothing else moved:

an  =  a(n).a_n \;=\; a(n).an​=a(n).

The input nnn is called the index. Because the domain is always a run of consecutive integers, the inputs arrive in a natural order, one after the next with nothing skipped, whether that run is finite, infinite, or starts at 000. That built-in order is exactly why a sequence is so naturally written as a list, in a way that most functions, whose inputs come in no particular order, are not. The list is not a second object sitting beside the function; it is the function’s output table, read from left to right.

Two habits are worth fixing right away. First, the index and the term play different roles and need not match: above, a3=10a_3 = 10a3​=10, so the index is 333 while the term is 101010. Second, order is part of the data. The set {2,5,10}\{2, 5, 10\}{2,5,10} does not care which element you name first, but the sequence 2,5,102, 5, 102,5,10 does, because every term is pinned to a particular index.

Since a sequence is a function, it has a graph: plot the point (n,an)(n, a_n)(n,an​) for each index nnn. But only the consecutive integers in the domain are legal inputs, so the graph is a scatter of separate dots and never a curve. There is no point above n=2.5n = 2.5n=2.5, because 2.52.52.5 is outside the domain, which means a2.5a_{2.5}a2.5​ names nothing at all.

Terms, indices, and what a list does not tell you

You can usually tell which kind of sequence is meant from how the list is written. When someone writes 3,7,11,153, 7, 11, 153,7,11,15 they mean a finite sequence with four terms, full stop. The trailing dots in 3,7,11,15,…3, 7, 11, 15, \ldots3,7,11,15,… signal an infinite one instead: the list keeps going by the same rule.

As the definition promised, indexing does not have to begin at 111. Some sequences are more natural starting from 000 (a bank balance before any interest has been added, say), and then the domain is {0,1,2,…}\{0, 1, 2, \ldots\}{0,1,2,…} and the first term is a0a_0a0​. The idea survives intact, because the inputs are still consecutive integers running upward from a stated place. What you may never do is leave that place unstated. That is because a3a_3a3​ is the fourth term when the count begins at 000, and the third term when it begins at 111. Every sequence in this lesson starts at n=1n = 1n=1 unless it says otherwise.

Now a warning that will save you a lot of grief: a few terms never determine how a sequence continues. This is about predicting more terms, not about a complete finite list: written all the way out, 3,7,11,153, 7, 11, 153,7,11,15 is the whole sequence, full stop, exactly as the paragraph above says. But shown the opening 2,4,6,8,…2, 4, 6, 8, \ldots2,4,6,8,… with no promise that it stops there, you would probably guess “the even numbers”, an=2na_n = 2nan​=2n, so the next term is 101010. That is why the rest of this lesson is about stating a rule precisely. That is also why a puzzle that shows four terms and asks “what comes next” has, strictly speaking, many right answers.

Explicit rules and recursive rules

There are two standard ways to pin a sequence down: state ana_nan​ directly, or build it from earlier terms. Each has a different cost, as the rest of this section shows.

An explicit rule (also called a closed form) gives ana_nan​ directly as an expression in nnn:

an=n2+1.a_n = n^2 + 1.an​=n2+1.

Want the 500500500th term? Substitute, and you are done: a500=5002+1=250,001a_{500} = 500^2 + 1 = 250{,}001a500​=5002+1=250,001. You never had to look at any other term.

A recursive rule instead gives one or more starting values, called seeds, and then a rule that builds each new term out of earlier ones:

a1=2,an=an−1+2n−1for n≥2.a_1 = 2, \qquad a_n = a_{n-1} + 2n - 1 \quad \text{for } n \ge 2.a1​=2,an​=an−1​+2n−1for n≥2.

Run it: a2=2+3=5a_2 = 2 + 3 = 5a2​=2+3=5, then a3=5+5=10a_3 = 5 + 5 = 10a3​=5+5=10, then a4=10+7=17a_4 = 10 + 7 = 17a4​=10+7=17. Those are the same terms the explicit rule produced, which is not a coincidence, and here is why, in a moment.

The seed is not decoration. Delete it and the rule no longer pins down one particular sequence. The bare rule an=an−1+2n−1a_n = a_{n-1} + 2n - 1an​=an−1​+2n−1 for n≥2n \ge 2n≥2 is obeyed by 2,5,10,17,…2, 5, 10, 17, \ldots2,5,10,17,…, and equally by 0,3,8,15,…0, 3, 8, 15, \ldots0,3,8,15,…, and by infinitely many other sequences, one for every choice of a1a_1a1​. The rule tells you how to take a step; the seed tells you where you are standing when you take the first one. Leaving it out is the most common error in this chapter.

Some recursions look back further than one step and therefore need more than one seed. To compute a3a_3a3​ from the rule an=an−1+an−2a_n = a_{n-1} + a_{n-2}an​=an−1​+an−2​ for n≥3n \ge 3n≥3 you need both a2a_2a2​ and a1a_1a1​, so both have to be handed to you. The famous choice a1=1a_1 = 1a1​=1 and a2=1a_2 = 1a2​=1 produces 1,1,2,3,5,8,13,…1, 1, 2, 3, 5, 8, 13, \ldots1,1,2,3,5,8,13,…, the Fibonacci sequence. In general, a recursion that reaches back kkk steps needs kkk seeds, since the rule alone can never produce the first kkk terms.

Worked example 1 List the first four terms of an=(−1)n(n+1)2na_n = \dfrac{(-1)^n (n+1)}{2n}an​=2n(−1)n(n+1)​

Substitute n=1,2,3,4n = 1, 2, 3, 4n=1,2,3,4 in turn, and let the factor (−1)n(-1)^n(−1)n do the sign work: it is −1-1−1 at odd indices and +1+1+1 at even ones.

At n=1n = 1n=1 and n=2n = 2n=2,

a1=(−1)1(2)2=−1,a2=(−1)2(3)4=34.a_1 = \frac{(-1)^1 (2)}{2} = -1, \qquad a_2 = \frac{(-1)^2 (3)}{4} = \frac{3}{4}.a1​=2(−1)1(2)​=−1,a2​=4(−1)2(3)​=43​.

At n=3n = 3n=3 and n=4n = 4n=4, reduce each fraction as you go:

a3=(−1)3(4)6=−46=−23,a4=(−1)4(5)8=58.a_3 = \frac{(-1)^3 (4)}{6} = -\frac{4}{6} = -\frac{2}{3}, \qquad a_4 = \frac{(-1)^4 (5)}{8} = \frac{5}{8}.a3​=6(−1)3(4)​=−64​=−32​,a4​=8(−1)4(5)​=85​.

So the sequence opens −1, 34, −23, 58,…-1, \ \frac{3}{4}, \ -\frac{2}{3}, \ \frac{5}{8}, \ldots−1, 43​, −32​, 85​,… A factor of (−1)n(-1)^n(−1)n is the standard way to make a sequence alternate in sign, and it is worth recognising on sight.

Worked example 2 Find a5a_5a5​ for the recursion a1=2a_1 = 2a1​=2, a2=5a_2 = 5a2​=5, an=an−1+2an−2a_n = a_{n-1} + 2a_{n-2}an​=an−1​+2an−2​ for n≥3n \ge 3n≥3

This rule reaches back two steps, so it comes with two seeds, and you cannot jump straight to a5a_5a5​. Build the terms in order.

The rule at n=3n = 3n=3 uses the two seeds:

a3=a2+2a1=5+2(2)=9.a_3 = a_2 + 2a_1 = 5 + 2(2) = 9.a3​=a2​+2a1​=5+2(2)=9.

Now a3a_3a3​ and a2a_2a2​ give a4a_4a4​, and then a4a_4a4​ and a3a_3a3​ give a5a_5a5​:

a4=a3+2a2=9+2(5)=19,a5=a4+2a3=19+2(9)=37.a_4 = a_3 + 2a_2 = 9 + 2(5) = 19, \qquad a_5 = a_4 + 2a_3 = 19 + 2(9) = 37.a4​=a3​+2a2​=9+2(5)=19,a5​=a4​+2a3​=19+2(9)=37.

The sequence is 2,5,9,19,37,…2, 5, 9, 19, 37, \ldots2,5,9,19,37,… Notice what the answer cost: two intermediate terms, a3a_3a3​ and a4a_4a4​, computed only to get to the one value asked for. Reaching a100a_{100}a100​ this way would mean computing a3a_3a3​ through a100a_{100}a100​ first, 989898 more terms, which is exactly the weakness an explicit rule fixes.

Here is why that is no coincidence, in plain terms. Go back to the explicit rule an=n2+1a_n = n^2 + 1an​=n2+1 and its recursion a1=2a_1 = 2a1​=2, an=an−1+2n−1a_n = a_{n-1} + 2n - 1an​=an−1​+2n−1: both start from the same value, 222. And at every step after that, both do the exact same thing to get the next term. The explicit rule’s value goes up by 2n−12n - 12n−1 each time nnn increases by 111, since (n2+1)−((n−1)2+1)=2n−1(n^2+1) - \big((n-1)^2+1\big) = 2n - 1(n2+1)−((n−1)2+1)=2n−1, and that is exactly the step the recursive rule takes. Two rules that start in the same place and always take the same step land on the same value at every step after that, all the way out. That is also why the labour differs even though the answer does not: the explicit rule hands you a100=1002+1=10,001a_{100} = 100^2 + 1 = 10{,}001a100​=1002+1=10,001 in a single substitution, while the recursion reaches the same number only after 999999 additions.

“All the way out” is doing real work in that explanation. The full argument that makes it airtight for every positive integer, not only the ones checked by hand, is in the Go deeper section at the end of this lesson.

See the full argument

That is the trade in general. A recursive rule is usually the easier one to write down, because it often states plainly what is happening. Such a rule often says: add the next odd number, double the previous term, add the last two. An explicit rule is the one you want when you need a distant term, because it does not care how far out you go. Neither kind is more correct than the other. They are two descriptions of one function, and a good deal of the skill in this chapter is moving between them.

Sigma notation

Sequences get added. To say “add the first fifty terms of aaa” you could write a1+a2+⋯+a50a_1 + a_2 + \cdots + a_{50}a1​+a2​+⋯+a50​. But those dots are an instruction to the reader rather than a definition, and they get worse as soon as the pattern of the terms is not obvious. Mathematics has a compact and unambiguous symbol for the job.

Definition. For indices m≤pm \le pm≤p in the sequence’s domain,

∑k=mpak  =  am+am+1+am+2+⋯+ap.\sum_{k=m}^{p} a_k \;=\; a_m + a_{m+1} + a_{m+2} + \cdots + a_p .k=m∑p​ak​=am​+am+1​+am+2​+⋯+ap​.

The symbol ∑\sum∑ is a capital Greek sigma, the Greek SSS, standing for sum. Read the notation as an instruction: let kkk start at the lower limit mmm and walk up through the integers one at a time. Keep going until kkk reaches the upper limit ppp. Evaluate the expression to the right of the sigma at each value of kkk, and add every result. The letter kkk is the index of summation, and the expression being evaluated is the summand. Both limits are included, at the bottom and at the top.

Three features of that notation deserve to be said out loud.

The letter under the sigma is only a temporary name, a local label for the index. It appears only under the sigma and inside the summand, it vanishes the moment the sum is worked out, and the answer contains no trace of it. The formal name for a letter used this way is a dummy index:

∑k=14k2  =  ∑i=14i2  =  ∑j=14j2  =  1+4+9+16  =  30.\sum_{k=1}^{4} k^2 \;=\; \sum_{i=1}^{4} i^2 \;=\; \sum_{j=1}^{4} j^2 \;=\; 1 + 4 + 9 + 16 \;=\; 30 .k=1∑4​k2=i=1∑4​i2=j=1∑4​j2=1+4+9+16=30.

Rename the index to any fresh letter and the value cannot change, because the terms being added are untouched. The one restriction is that the new name must not already be doing another job in the expression. For instance, renaming kkk to nnn inside ∑k=1nk\sum_{k=1}^{n} k∑k=1n​k would be a disaster, since nnn is the upper limit there.

Counting the terms is an off-by-one trap. Running the index from mmm up to ppp produces the indices m,m+1,…,pm, m+1, \ldots, pm,m+1,…,p, and when m≤pm \le pm≤p there are

p−m+1p - m + 1p−m+1

of them. Subtracting the limits counts the steps between them, and a list always has one more entry than it has steps. So from k=3k = 3k=3 to k=8k = 8k=8 there are five steps but six terms, namely 3,4,5,6,7,83, 4, 5, 6, 7, 83,4,5,6,7,8.

The summand need not mention the index. In

∑k=157  =  7+7+7+7+7  =  35,\sum_{k=1}^{5} 7 \;=\; 7 + 7 + 7 + 7 + 7 \;=\; 35 ,k=1∑5​7=7+7+7+7+7=35,

the index still runs 1,2,3,4,51, 2, 3, 4, 51,2,3,4,5 and the summand is still evaluated five times. It simply returns 777 every time. The limits, not the summand, control how many terms there are, even when the summand never mentions the index at all.

A sum of terms of a sequence is called a series. Adding finitely many terms always produces an ordinary number, which is all this lesson needs. What an infinite sum could possibly mean is a real question, and a later lesson answers it.

Common mistakes

Common mistakes

  • Writing a recursion with no seed. The rule an=3an−1a_n = 3a_{n-1}an​=3an−1​ describes infinitely many sequences, one for every starting value. Without a1a_1a1​ it does not pin down any one of them. A rule that reaches back two steps needs two seeds.
  • Confusing the index with the term. In 5,9,13,175, 9, 13, 175,9,13,17 the third term is a3=13a_3 = 13a3​=13, not 333. The index says which term; the term is the value.
  • Off by one when counting terms. A sum from k=4k = 4k=4 to k=17k = 17k=17 has 17−4+1=1417 - 4 + 1 = 1417−4+1=14 terms, not 131313. Both limits are included, so subtracting them counts steps, not terms.
  • Believing the index name matters. Every one of ∑k=14k2\sum_{k=1}^{4} k^2∑k=14​k2, ∑i=14i2\sum_{i=1}^{4} i^2∑i=14​i2, and ∑j=14j2\sum_{j=1}^{4} j^2∑j=14​j2 is 303030. If your answer still contains the index letter, you have not finished.
  • Ignoring the index when the summand hides it. In ∑k=165\sum_{k=1}^{6} 5∑k=16​5 the value is 303030, not 555: six terms are added, and each one happens to be 555.
  • Joining the dots on the graph. A sequence has no term between a2a_2a2​ and a3a_3a3​, so its graph is a set of isolated points. Drawing a curve through them invents values that do not exist.
  • Trusting a pattern. Four terms never determine how a sequence continues. Until a rule is stated, “what comes next” has many correct answers.

Key takeaways

  • A sequence is a function whose domain is a run of consecutive integers, either all of them from some starting point (an infinite sequence) or just the first several (a finite sequence). That starting point is 111 unless the sequence is indexed from 000 or some other stated place. The notation ana_nan​ is just a(n)a(n)a(n) with the parentheses replaced by a subscript, so everything you know about functions still applies.
  • The index nnn and the term ana_nan​ play different roles and need not match, and the graph of a sequence is a set of separate dots, one above each index in the domain.
  • An explicit rule gives ana_nan​ as an expression in nnn and reaches any term in one substitution. A recursive rule gives seed values plus a rule for building each term from earlier ones, and it has to be climbed one rung at a time.
  • A recursion without its seed does not pin down one sequence. A rule that looks back kkk steps needs kkk seeds.
  • The notation ∑k=mpak\sum_{k=m}^{p} a_k∑k=mp​ak​ means am+am+1+⋯+apa_m + a_{m+1} + \cdots + a_pam​+am+1​+⋯+ap​. Both limits are included, so the sum has p−m+1p - m + 1p−m+1 terms.
  • The index of summation is a dummy: renaming it changes nothing, and it never appears in the answer.
  • A handful of terms never determines how a sequence continues. Only a stated rule does.

A single explicit rule that hides four matching terms and then breaks the pattern

The repeating list 2,4,6,8,2,4,6,8,…2, 4, 6, 8, 2, 4, 6, 8, \ldots2,4,6,8,2,4,6,8,… is one way to match 2,4,6,82, 4, 6, 82,4,6,8 without being the even numbers. Here is another, built entirely from a formula in nnn, which is closer to what “a rule” usually means in this course.

The rule

an=2n+(n−1)(n−2)(n−3)(n−4)a_n = 2n + (n-1)(n-2)(n-3)(n-4)an​=2n+(n−1)(n−2)(n−3)(n−4)

contains a product that is built to vanish at exactly n=1,2,3,4n = 1, 2, 3, 4n=1,2,3,4: each of those values makes one of the four factors 000. So at those four indices, only the 2n2n2n term survives, and the rule produces 2,4,6,82, 4, 6, 82,4,6,8, the same start as the even numbers. But at n=5n = 5n=5, none of the four factors is 000, so the product term switches on:

a5=2(5)+(5−1)(5−2)(5−3)(5−4)=10+(4)(3)(2)(1)=10+24=34.\begin{aligned} a_5 &= 2(5) + (5-1)(5-2)(5-3)(5-4) \\ &= 10 + (4)(3)(2)(1) = 10 + 24 = 34. \end{aligned}a5​​=2(5)+(5−1)(5−2)(5−3)(5−4)=10+(4)(3)(2)(1)=10+24=34.​

Both an=2na_n = 2nan​=2n and this rule are perfectly good sequences, and they agree at the first four indices and disagree at the fifth. Nothing about the first four terms could have told you which one you were looking at.

Why the explicit rule and the recursion define the same sequence at every index

The explicit rule an=n2+1a_n = n^2 + 1an​=n2+1 and the recursion a1=2a_1 = 2a1​=2, an=an−1+2n−1a_n = a_{n-1} + 2n - 1an​=an−1​+2n−1 define the same sequence#

Two sequences are the same function when they have the same domain and agree at every index. So what we must show is that these two rules produce the same term at every nnn.

Call the explicit sequence aaa, so that an=n2+1a_n = n^2 + 1an​=n2+1 for every positive integer nnn, and call the recursive one bbb, so that b1=2b_1 = 2b1​=2 and bn=bn−1+2n−1b_n = b_{n-1} + 2n - 1bn​=bn−1​+2n−1 for every n≥2n \ge 2n≥2.

Begin at the bottom of the ladder. The explicit rule gives a1=12+1=2a_1 = 1^2 + 1 = 2a1​=12+1=2, and the seed gives b1=2b_1 = 2b1​=2, so the two agree at n=1n = 1n=1.

Next, check that aaa obeys the very step rule that bbb was built from. For any n≥2n \ge 2n≥2,

an−an−1=(n2+1)−((n−1)2+1)=n2−(n2−2n+1)=2n−1,\begin{aligned} a_n - a_{n-1} &= (n^2 + 1) - \big((n-1)^2 + 1\big) \\ &= n^2 - (n^2 - 2n + 1) = 2n - 1, \end{aligned}an​−an−1​​=(n2+1)−((n−1)2+1)=n2−(n2−2n+1)=2n−1,​

and rearranging gives an=an−1+2n−1a_n = a_{n-1} + 2n - 1an​=an−1​+2n−1, which is exactly the rule bbb follows.

Now climb. Suppose the two sequences agree at some index n−1n - 1n−1, so an−1=bn−1a_{n-1} = b_{n-1}an−1​=bn−1​. Each one then adds the same quantity 2n−12n - 12n−1 to that same value to produce its next term, so an=bna_n = b_nan​=bn​. Agreement at any index therefore forces agreement at the next index. We already have agreement at n=1n = 1n=1, so it propagates to n=2n = 2n=2, and from there to n=3n = 3n=3, and on through every positive integer. No index can be the first place the two disagree, because the value there is computed from the index below it, where by assumption they already agree.

The two rules describe the same function, so they describe the same sequence.

∎

A sum written two different correct ways

Starting the index at 000 instead of 111, and adjusting the summand to compensate, describes the exact same sum:

∑k=15kk+1  =  ∑j=04j+1j+2.\sum_{k=1}^{5} \frac{k}{k+1} \;=\; \sum_{j=0}^{4} \frac{j+1}{j+2} .k=1∑5​k+1k​=j=0∑4​j+2j+1​.

Check a couple of terms to see why: at j=0j = 0j=0 the second sum’s summand is 12\frac{1}{2}21​, matching the first sum’s term at k=1k = 1k=1; at j=4j = 4j=4 it is 56\frac{5}{6}65​, matching k=5k = 5k=5. Both versions produce the same five terms in the same order. Sigma notation is a way of writing a sum, not a fingerprint of it, so a sum can always be written in more than one equivalent way. Prefer whichever version has the simplest summand.

A bit of history (optional)

Before the symbol arrived, a long sum had to be described rather than written down. An author named the pattern in a sentence, or set out a few terms and trailed off into dots. Dots are an instruction to guess. They promise that the pattern continues, and then leave the reader to work out how.

Leonhard Euler, a Swiss mathematician, introduced the symbol in 1755. He borrowed the Greek capital SSS, the letter sigma, and made it stand for the Latin word summa, meaning sum. He used it in his textbook on the calculus. The choice looks obvious now, but at the time it was not: earlier mathematicians had tried other shorthand for a long sum, none of which caught on the way Euler’s sigma eventually did.

What the sigma really adds is not brevity, though it is certainly shorter. It is the limits. The finished notation states where the index begins, where it stops, and which term is evaluated at each step. Nothing whatever is left to the reader’s judgement. A phrase that had depended on the goodwill of whoever read it became an instruction a machine could execute.

So the parts of the symbol deserve the attention this lesson gave them. The upper limit, the lower limit and the summand are not trim around a sum sign. They are the entire content of Euler’s improvement. The index perched underneath belongs to nobody, since renaming it changes nothing at all.
