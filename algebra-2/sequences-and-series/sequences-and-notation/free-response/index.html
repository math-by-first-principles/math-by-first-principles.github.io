    1. A sequence read as a function . Foundational, 11 points. Question 1 of 5.

    Foundational 11 pts

    A sequence is nothing more than a function whose inputs are restricted to the positive integers. This question asks you to use that fact directly: substitute into a rule the way you would for any function, and pay attention to which number the rule is being fed and which number it hands back.

    1. A

    2. B

      Explain what it means Words, not just symbols. Say what the number is telling you about the situation. 3 points

      Explain why it works A sentence or two. Reasons, not steps. 3 points

    Worked solution

    Part A

    Treat ana_nan​ exactly as you would a(n)a(n)a(n): substitute the index in place of nnn and simplify.

    For the first four terms,

    a1=12+2(1)−1=2,a2=22+2(2)−1=7,a_1 = 1^2 + 2(1) - 1 = 2, \qquad a_2 = 2^2 + 2(2) - 1 = 7,a1​=12+2(1)−1=2,a2​=22+2(2)−1=7,

    a20=202+2(20)−1=400+40−1=439.a_{20} = 20^2 + 2(20) - 1 = 400 + 40 - 1 = 439.a20​=202+2(20)−1=400+40−1=439.

    Part B

    Read the definition backward from the value. Substituting n=3n = 3n=3 into the rule from part A confirms which index is responsible:

    a3=32+2(3)−1=14.a_3 = 3^2 + 2(3) - 1 = 14.a3​=32+2(3)−1=14.

    So the index that produced 141414 is 333, not 141414 itself.

    The confusion "the index is 141414" mixes up the two roles a sequence keeps separate: the index tells you WHICH term of the list you are looking at, and the term is WHAT that entry is worth. Here the index is the small number 333, counting a position in the list, while 141414 is the (generally much larger) output the rule produced once it was fed that position. Nothing about the size of a term says anything about the size of the index that produced it.

    Part C

    The reason has nothing to do with this particular formula, so the argument should not appeal to it. A sequence is a function whose domain is fixed in advance:

    domain={1,2,3,…}.\text{domain} = \{1, 2, 3, \ldots\}.domain={1,2,3,…}.

    Asking for a2.5a_{2.5}a2.5​ is asking the function to accept an input, 2.52.52.5, that was never in its domain to begin with.

    This is exactly the situation of an ordinary function evaluated outside where it is defined: the expression is not a hard computation that happens to give a strange answer, it is not a legitimate question about the function at all. Substituting 2.52.52.5 into the formula n2+2n−1n^2 + 2n - 1n2+2n−1 would certainly produce a number, but that number would not be a term of this sequence, because the sequence was never asked to say anything about non-integer inputs.

    2. Climbing a rule that looks back two terms . Application, 11 points. Question 2 of 5.

    Application 11 pts

    Some recursive rules need only the term directly before the one being built. Others reach back further, and when a rule reaches back two terms it needs two starting values before it can produce anything at all.

    1. A
      Part A.

      A sequence is given by the seeds c1=3c_1 = 3c1​=3, c2=4c_2 = 4c2​=4, and the rule cn=cn−1+cn−2+1c_n = c_{n-1} + c_{n-2} + 1cn​=cn−1​+cn−2​+1 for n≥3n \ge 3n≥3. Find c3c_3c3​, c4c_4c4​, and c5c_5c5​.

    2. B

      Explain why it works A sentence or two. Reasons, not steps. 4 points

    3. C
      Part C.

      Suppose instead a rule reached back three terms, dn=dn−1+dn−2+dn−3d_n = d_{n-1} + d_{n-2} + d_{n-3}dn​=dn−1​+dn−2​+dn−3​. How many seed values would this rule need before a single term could be computed, and which specific terms are needed to compute d4d_4d4​?

    The answer

    Part A

    c3=8c_3 = 8c3​=8, c4=13c_4 = 13c4​=13, and c5=22c_5 = 22c5​=22.

    Part B

    Because the rule looks back only two terms at a time, computing c5c_5c5​ needs c4c_4c4​ and c3c_3c3​ already known, and c4c_4c4​ itself needs c3c_3c3​ and c2c_2c2​; so c3c_3c3​, then c4c_4c4​, must be computed before c5c_5c5​ can be.

    Part C

    It would need three seeds, d1d_1d1​, d2d_2d2​, d3d_3d3​. Computing d4d_4d4​ needs exactly those three values.

    Worked solution

    Part A

    This rule needs two terms back, so both seeds are used immediately, and each new term uses the two terms directly before it.

    At n=3n = 3n=3, both seeds are used:

    c3=c2+c1+1=4+3+1=8.c_3 = c_2 + c_1 + 1 = 4 + 3 + 1 = 8.c3​=c2​+c1​+1=4+3+1=8.

    The next two terms each use the pair just computed:

    c4=c3+c2+1=8+4+1=13,c5=c4+c3+1=13+8+1=22.c_4 = c_3 + c_2 + 1 = 8 + 4 + 1 = 13, \qquad c_5 = c_4 + c_3 + 1 = 13 + 8 + 1 = 22.c4​=c3​+c2​+1=8+4+1=13,c5​=c4​+c3​+1=13+8+1=22.

    Each term used the two terms immediately before it, never anything further back.

    Part B

    "Looking back two terms" describes what one application of the rule uses, not how far the rule can reach in total. Applying the rule at n=5n = 5n=5 requires c4c_4c4​ and c3c_3c3​, neither of which is a seed:

    c5=c4+c3+1.c_5 = c_4 + c_3 + 1.c5​=c4​+c3​+1.

    So before c5c_5c5​ can be produced, c3c_3c3​ has to be built from the two seeds, and then c4c_4c4​ has to be built from c3c_3c3​ and c2c_2c2​. Only once both of those exist does the rule at n=5n = 5n=5 have the two ingredients it needs. There is no shortcut that lets the rule reach directly from c1c_1c1​ and c2c_2c2​ to c5c_5c5​: every rung of the ladder between the seeds and the target term has to be climbed.

    Part C

    The pattern from parts A and B generalizes directly. A rule that reaches back kkk terms cannot be applied until kkk consecutive terms already exist to feed it, and the only way to have terms with no earlier terms behind them is to state them as seeds.

    For dn=dn−1+dn−2+dn−3d_n = d_{n-1} + d_{n-2} + d_{n-3}dn​=dn−1​+dn−2​+dn−3​, the first index the rule can be applied at is n=4n = 4n=4, and applying it there uses d3d_3d3​, d2d_2d2​, and d1d_1d1​, all three at once:

    d4=d3+d2+d1.d_4 = d_3 + d_2 + d_1.d4​=d3​+d2​+d1​.

    None of those three can be produced by the rule itself, since each of them would need terms with an even smaller index, running past where the sequence starts. So all three, d1d_1d1​, d2d_2d2​, d3d_3d3​, have to be given directly, and d4d_4d4​ is the first term the rule actually builds.

    In one line

    With seeds c1=3c_1 = 3c1​=3, c2=4c_2 = 4c2​=4 and cn=cn−1+cn−2+1c_n = c_{n-1} + c_{n-2} + 1cn​=cn−1​+cn−2​+1: c3=8c_3 = 8c3​=8, c4=13c_4 = 13c4​=13, c5=22c_5 = 22c5​=22, each built from the two terms directly before it. Reaching c5c_5c5​ needs c4c_4c4​ and c3c_3c3​ computed first, since the rule only ever sees two terms back at a time and neither c4c_4c4​ nor c3c_3c3​ is a seed. In general, a rule reaching back kkk terms needs kkk seeds: a rule reaching back three terms needs d1d_1d1​, d2d_2d2​, d3d_3d3​ before d4d_4d4​, its first computable term, can be found.

    3. Why the seed is not decoration . Reasoning, 10 points. Question 3 of 5.

    Reasoning 10 pts

    A recursive rule with no starting value looks like it says everything there is to say about the sequence. It does not. This question asks you to show exactly how much a bare rule leaves undecided, and why that gap never closes as the sequence runs on.

    1. A
      Part A.

      Consider the bare rule en=en−1+3ne_n = e_{n-1} + 3nen​=en−1​+3n for n≥2n \ge 2n≥2, written with no seed stated. A classmate claims this rule by itself pins down exactly one sequence. Decide whether the claim is true, and support your decision by producing two sequences that both obey the rule but disagree from the very first term.

      Justify your claim State the claim, then give the reason it has to be true. 5 points

    2. B
      Part B.

      Let eee and fff be two sequences that both obey xn=xn−1+3nx_n = x_{n-1} + 3nxn​=xn−1​+3n for n≥2n \ge 2n≥2, but with different seeds, e1≠f1e_1 \neq f_1e1​=f1​. Prove that en≠fne_n \neq f_nen​=fn​ for every positive integer nnn, not merely at n=1n = 1n=1.

      Complete the derivation Each line should follow from the one above it. Say what lets you take each step. 5 points

    Hints

    One at a time, each one a step further than the last. Take only as many as you need.

    1. Hint 1 of 3

      A bare recursive rule fixes only how to get from one term to the next. Nothing in it says where to start, so ask whether more than one starting point could be made to obey it.

    2. Hint 2 of 3 · Part A

      Pick two different values for e1e_1e1​ and run the rule forward from each one a few steps. Compare the two resulting lists.

    3. Hint 3 of 3 · Part B

      Do not track ene_nen​ and fnf_nfn​ separately. Track the single quantity en−fne_n - f_nen​−fn​ instead, and ask what the rule does to it at each step.

    That is every hint for this question.

    Answer and solution

    Check your answer first. If it is wrong, go back to your paper: the worked solution will still be here.

    The answer

    Part A

    The claim is false. With seed e1=1e_1 = 1e1​=1 the rule produces 1,7,16,28,…1, 7, 16, 28, \ldots1,7,16,28,…, and with seed e1=4e_1 = 4e1​=4 it produces 4,10,19,31,…4, 10, 19, 31, \ldots4,10,19,31,…; both obey the rule, but they disagree at every term shown.

    Part B

    The difference en−fne_n - f_nen​−fn​ equals e1−f1e_1 - f_1e1​−f1​ at every nnn, since both sequences add the same amount 3n3n3n at each step; because e1≠f1e_1 \neq f_1e1​=f1​, that difference is never zero, so en≠fne_n \neq f_nen​=fn​ for every nnn.

    Not what you got? Look for the slip on your own paper before you open the solution. Finding it yourself is worth more than reading it.

    Worked solution

    Part A

    A bare rule fixes only the STEP from one term to the next, so testing the claim means checking whether two different starting choices can both be made to obey it.

    Take e1=1e_1 = 1e1​=1 and apply the rule three times:

    e2=1+3(2)=7,e3=7+3(3)=16,e4=16+3(4)=28.e_2 = 1 + 3(2) = 7, \qquad e_3 = 7 + 3(3) = 16, \qquad e_4 = 16 + 3(4) = 28.e2​=1+3(2)=7,e3​=7+3(3)=16,e4​=16+3(4)=28.

    Now take e1=4e_1 = 4e1​=4 instead, and apply the same rule:

    e2=4+3(2)=10,e3=10+3(3)=19,e4=19+3(4)=31.e_2 = 4 + 3(2) = 10, \qquad e_3 = 10 + 3(3) = 19, \qquad e_4 = 19 + 3(4) = 31.e2​=4+3(2)=10,e3​=10+3(3)=19,e4​=19+3(4)=31.

    Both 1,7,16,28,…1, 7, 16, 28, \ldots1,7,16,28,… and 4,10,19,31,…4, 10, 19, 31, \ldots4,10,19,31,… satisfy en=en−1+3ne_n = e_{n-1} + 3nen​=en−1​+3n at every step, and yet they are two different sequences that never agree. So the bare rule does not pin down one sequence; it describes an entire family of them, one for every choice of e1e_1e1​.

    Part B

    What has to be shown is that the gap present at the seed never closes, however far the sequences run. Work with the difference en−fne_n - f_nen​−fn​ directly.

    At n=1n = 1n=1, the difference is e1−f1e_1 - f_1e1​−f1​ by definition, and this is nonzero by hypothesis.

    Now suppose the difference at some index n−1n - 1n−1 (with n≥2n \ge 2n≥2) equals e1−f1e_1 - f_1e1​−f1​. Both sequences obey the same rule, so each adds the identical quantity 3n3n3n to move from index n−1n-1n−1 to index nnn:

    en−fn=(en−1+3n)−(fn−1+3n)=en−1−fn−1.e_n - f_n = (e_{n-1} + 3n) - (f_{n-1} + 3n) = e_{n-1} - f_{n-1}.en​−fn​=(en−1​+3n)−(fn−1​+3n)=en−1​−fn−1​.

    By the assumption for index n−1n - 1n−1, that last quantity is e1−f1e_1 - f_1e1​−f1​. So the difference at index nnn is again e1−f1e_1 - f_1e1​−f1​, unchanged from the difference one step earlier.

    The difference therefore equals e1−f1e_1 - f_1e1​−f1​ at n=1n = 1n=1, and each step forces the next index to inherit that exact same value, so it equals e1−f1e_1 - f_1e1​−f1​ at every positive integer nnn. Since e1≠f1e_1 \neq f_1e1​=f1​, this common value is nonzero at every index, so en≠fne_n \neq f_nen​=fn​ for every nnn. The gap created by the two different seeds never narrows, because the rule adds the same amount to both sequences at every step and an equal addition to two unequal numbers cannot make them equal.

    In one line

    The claim is false: with e1=1e_1 = 1e1​=1 the rule en=en−1+3ne_n = e_{n-1} + 3nen​=en−1​+3n gives 1,7,16,28,…1, 7, 16, 28, \ldots1,7,16,28,…, and with e1=4e_1 = 4e1​=4 it gives 4,10,19,31,…4, 10, 19, 31, \ldots4,10,19,31,…, two sequences that both obey the rule but disagree throughout. In general, if eee and fff obey the same rule with e1≠f1e_1 \neq f_1e1​=f1​, the difference en−fne_n - f_nen​−fn​ equals e1−f1e_1 - f_1e1​−f1​ at every index, because the identical quantity 3n3n3n is added to both sequences at each step and cancels out of the difference. A nonzero gap at the seed is therefore a nonzero gap forever, which is exactly why a recursive rule without its seed defines no single sequence at all.

    The answer

    Part A

    Renaming the index only relabels the same list of positive-integer inputs and the same rule applied to them, provided the new letter is not already in use elsewhere in the expression; the numbers actually being added are untouched, so the total is unchanged.

    Part B

    The renaming is illegitimate because mmm already names the sum's upper limit; reusing it as the index makes that one letter play two different roles at once, so the rewritten expression no longer has a clear meaning.

    Part C

    ∑k=mp1=p−m+1\displaystyle\sum_{k=m}^{p} 1 = p - m + 1k=m∑p​1=p−m+1, because the sum adds 111 once for every index from mmm to ppp, so its value is exactly the count of those indices; this proves directly that a sum running from mmm to ppp has p−m+1p - m + 1p−m+1 terms, since here the sum's value and the term count are the same number.

    Worked solution

    Part A

    The index is not itself a term of the sum; it is an instruction for which values of aka_kak​ to add. Whatever letter carries that instruction, the instruction says the same thing: start at mmm, walk up through the integers one at a time, stop at ppp, and add the value of aaa at each stop:

    ∑k=mpak=am+am+1+⋯+ap.\sum_{k=m}^{p} a_k = a_m + a_{m+1} + \cdots + a_p.∑k=mp​ak​=am​+am+1​+⋯+ap​.

    Changing the letter used for that walk, from kkk to any other symbol not already in use elsewhere in the expression, changes nothing about which integers are walked through or what is evaluated at each one. The list of numbers actually being added, am,am+1,…,apa_m, a_{m+1}, \ldots, a_pam​,am+1​,…,ap​, is identical either way, and a sum of the same list of numbers has the same total.

    That is also why the index vanishes once the sum is worked out: it never named a value in the answer, only a rule for producing the list of values that got added.

    Part B

    A renaming is only safe when the new letter is not already doing another job in the expression, and here it is: mmm was the upper limit before the student ever touched the index.

    After the substitution, the same symbol mmm is asked to name the fixed upper limit of the sum and, at the same time, the value that walks from 111 up to that limit one step at a time. Those are two different jobs, a constant and a variable, and one letter cannot honestly do both in the same expression:

    ∑m=1m(3m−m).\sum_{m=1}^{m} (3m - m).∑m=1m​(3m−m).

    That expression does not describe the original sum, or indeed any sum with a clear meaning at all, since it is unclear at any point which occurrence of mmm is the fixed limit and which is the walking index.

    The fix is to choose a letter not already in use anywhere in the expression, for instance jjj: ∑j=1m(3j−m)\sum_{j=1}^{m}(3j-m)∑j=1m​(3j−m) says exactly what the original sum said.

    Part C

    This sum is unusual in one useful way: because the summand is always 111, the value of the sum and the number of terms it has are literally the same quantity, so proving the sum equals p−m+1p - m + 1p−m+1 is the same as proving the term-count rule directly.

    The index kkk runs through the consecutive integers m,m+1,m+2,…,pm, m+1, m+2, \ldots, pm,m+1,m+2,…,p. Shift every one of them down by m−1m - 1m−1: the list becomes

    1,2,3,…,p−m+1,1, 2, 3, \ldots, p - m + 1,1,2,3,…,p−m+1,

    and shifting every entry of a list by the same amount changes none of the entries relative to each other and drops none of them, so this new list has exactly as many entries as the original one. The shifted list is plainly the consecutive integers from 111 to p−m+1p - m + 1p−m+1, which has p−m+1p - m + 1p−m+1 entries.

    Since the original list of indices has that same count, and the sum adds exactly 111 once for each index in that list,

    ∑k=mp1=1+1+⋯+1⏟p−m+1 times=p−m+1.\sum_{k=m}^{p} 1 = \underbrace{1 + 1 + \cdots + 1}_{p-m+1 \text{ times}} = p - m + 1.∑k=mp​1=p−m+1 times1+1+⋯+1​​=p−m+1.

    Because this sum's value is, by construction, nothing other than a count of how many indices ran from mmm to ppp, this single computation proves the general counting rule: any sum whose index runs from mmm to ppp, whatever its summand, has p−m+1p - m + 1p−m+1 terms.

    In one line

    Renaming the index of ∑k=mpak\displaystyle\sum_{k=m}^{p} a_kk=m∑p​ak​ never changes its value, provided the new letter is not already in use elsewhere in the expression, because the index only names which values of aka_kak​ get added, and that list is untouched by the relabeling.
