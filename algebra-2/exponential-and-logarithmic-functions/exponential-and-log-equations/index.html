Solving Exponential and Logarithmic Equations

Intuition

You undo addition by subtracting and you undo multiplication by dividing. To solve 2x=322^x = 322x=32 you need to undo an exponent, and the logarithm is exactly that undo button. But an undo button can only exist when a function never repeats a value. After all, if two different inputs produced the same output, there would be no way to know which input to come back to. Exponentials never repeat a value, and neither do logarithms. That one fact is the licence behind every move in this lesson. It also tells you when a move is not safe, and that is where extraneous solutions come from.

Learning goals

  • Use one-to-oneness to equate exponents on a common base
  • Take a logarithm to bring an unknown exponent down
  • Turn log⁡bu=k\log_b u = klogb​u=k into u=bku = b^ku=bk
  • Check every candidate when combining logs enlarges the domain
  • Reject a substitution value u≤0u \le 0u≤0, which yields no xxx
  • State a rounded answer as rounded, keeping the exact form

One-to-one is the licence

Return to the equation from the box above, 2x=322^x = 322x=32. Since 32=2532 = 2^532=25, the equation is really 2x=252^x = 2^52x=25. The exponents must match because the bases already do, so x=5x = 5x=5. That move, matching exponents because the bases match, is worth naming precisely, because every technique in this lesson is some version of it.

A function fff is one-to-one when different inputs always give different outputs, or equivalently, when f(u)=f(v)f(u) = f(v)f(u)=f(v) forces u=vu = vu=v. On a graph this says that no horizontal line meets the curve twice. That is precisely the condition you met in Inverse Functions: a function has an inverse exactly when it is one-to-one. The reason is that the inverse has to send each output back to a single input.

Fix a base bbb with b>0b > 0b>0 and b≠1b \neq 1b=1. The logarithm log⁡b\log_blogb​ was defined as the inverse of f(x)=bxf(x) = b^xf(x)=bx, so the two of them cancel:

log⁡b ⁣(bt)=tfor every real t,blog⁡bM=Mfor every M>0.\log_b\!\left(b^t\right) = t \quad \text{for every real } t, \qquad\qquad b^{\log_b M} = M \quad \text{for every } M > 0.logb​(bt)=tfor every real t,blogb​M=Mfor every M>0.

Read them in words. The first says: the exponent you must put on bbb to get btb^tbt is ttt. The second says: if you put the exponent log⁡bM\log_b Mlogb​M on bbb, you get MMM. Everything below is squeezed out of these two identities.

Equating exponents and equating arguments#

Take a base bbb with b>0b > 0b>0 and b≠1b \neq 1b=1.

Suppose first that bu=bvb^u = b^vbu=bv. Apply log⁡b\log_blogb​ to both sides. A function gives one output per input, so feeding it the same number twice gives the same answer twice, and log⁡b(bu)=log⁡b(bv)\log_b(b^u) = \log_b(b^v)logb​(bu)=logb​(bv). The first cancellation identity turns the left side into uuu and the right side into vvv, so u=vu = vu=v. The converse is immediate: if u=vu = vu=v, then bub^ubu and bvb^vbv are the very same number. So bu=bvb^u = b^vbu=bv holds exactly when u=vu = vu=v, with no side conditions at all, since btb^tbt is defined for every real ttt.

Notice where the requirement b≠1b \neq 1b=1 earns its keep. Since 1u=11^u = 11u=1 for every uuu, we have 12=151^2 = 1^512=15 while 2≠52 \neq 52=5. A base of 111 repeats a value, so it is not one-to-one and it has no undo button. The same goes for b=0b = 0b=0, since 0t=00^t = 00t=0 for every t>0t > 0t>0. A negative base fails for a different reason, and b=−2b = -2b=−2 shows it plainly: (−2)1/2(-2)^{1/2}(−2)1/2 is not a real number at all, so btb^tbt is not even defined for every real ttt, and there is no unbroken curve to invert in the first place. That is why logarithms are built only on bases that are positive and different from 111.

Now suppose MMM and NNN are positive and log⁡bM=log⁡bN\log_b M = \log_b Nlogb​M=logb​N. Raise bbb to each side: blog⁡bM=blog⁡bNb^{\log_b M} = b^{\log_b N}blogb​M=blogb​N. The second cancellation identity turns the left side into MMM and the right side into NNN, so M=NM = NM=N. Here the converse needs that positivity. If M=NM = NM=N and both are positive, then log⁡bM\log_b Mlogb​M and log⁡bN\log_b Nlogb​N are the same number and the log equation holds. Drop the positivity and the converse collapses, because log⁡b(−4)\log_b(-4)logb​(−4) is not a number at all, so M=N=−4M = N = -4M=N=−4 does not produce a true statement about logarithms.

That asymmetry is worth staring at. Equating exponents is a two-way street. Equating arguments is a two-way street only on positive arguments, and every extraneous solution in this lesson comes from stepping off the street.

∎

Solving exponential equations

An exponential equation has the unknown in an exponent. There are two techniques, and which one you reach for depends on whether the two sides can be written with a common base.

Technique 1: match the bases. If both sides are powers of the same base, the theorem lets you throw the base away and set the exponents equal. For 8x=4x+18^x = 4^{x+1}8x=4x+1, write everything in base 222:

23x=22x+2  ⟹  3x=2x+2  ⟹  x=2.2^{3x} = 2^{2x + 2} \;\Longrightarrow\; 3x = 2x + 2 \;\Longrightarrow\; x = 2.23x=22x+2⟹3x=2x+2⟹x=2.

Worked example 1 Solve 9x+1=27x−19^{x+1} = 27^{x-1}9x+1=27x−1

Neither side is a whole-number power of the other, but 999 and 272727 are both powers of 333, so rewrite them:

9x+1=(32)x+1=32x+2,27x−1=(33)x−1=33x−3.9^{x+1} = \left(3^2\right)^{x+1} = 3^{2x+2}, \qquad 27^{x-1} = \left(3^3\right)^{x-1} = 3^{3x-3}.9x+1=(32)x+1=32x+2,27x−1=(33)x−1=33x−3.

Both sides now sit on the same base, so the exponents must be equal:

2x+2=3x−3  ⟹  x=5.2x + 2 = 3x - 3 \;\Longrightarrow\; x = 5.2x+2=3x−3⟹x=5.

Check it in the original equation. With x=5x = 5x=5, the left side is 96=(32)6=3129^6 = (3^2)^6 = 3^{12}96=(32)6=312 and the right side is 274=(33)4=31227^4 = (3^3)^4 = 3^{12}274=(33)4=312, so both sides really are the same number.

Technique 2: take a logarithm of both sides. A common base is a luxury. In 5x=405^x = 405x=40 there is none, because 404040 is not a whole-number power of 555 that you can spot by inspection. Both sides are positive, though (5x>05^x > 05x>0 for every xxx, and 40>040 > 040>0), so both sides have a logarithm. Applying the one-to-one function log⁡\loglog to both sides therefore produces an equation with exactly the same solutions. Use the common logarithm log⁡\loglog, which is log⁡10\log_{10}log10​:

log⁡ ⁣(5x)=log⁡40  ⟹  xlog⁡5=log⁡40  ⟹  x=log⁡40log⁡5.\log\!\left(5^x\right) = \log 40 \;\Longrightarrow\; x \log 5 = \log 40 \;\Longrightarrow\; x = \frac{\log 40}{\log 5}.log(5x)=log40⟹xlog5=log40⟹x=log5log40​.

The middle step is the power rule from Properties of Logarithms. That power rule is the whole point of taking a log: it drags the unknown down out of the exponent, where ordinary algebra can reach it.

That quotient is the change-of-base formula in action. Setting y=log⁡540y = \log_5 40y=log5​40 means 5y=405^y = 405y=40, and taking log⁡\loglog of both sides gives ylog⁡5=log⁡40y \log 5 = \log 40ylog5=log40, which is the computation we just did. So

log⁡bM=log⁡Mlog⁡b,\log_b M = \frac{\log M}{\log b},logb​M=logblogM​,

and change of base is not a separate trick but the same move applied to the definition. Numerically, log⁡40≈1.60206\log 40 \approx 1.60206log40≈1.60206 and log⁡5≈0.69897\log 5 \approx 0.69897log5≈0.69897, so

x=log⁡40log⁡5≈2.29203.x = \frac{\log 40}{\log 5} \approx 2.29203.x=log5log40​≈2.29203.

The exact answer is x=log⁡540x = \log_5 40x=log5​40. Rounded to three decimal places, x≈2.292x \approx 2.292x≈2.292. Keep those two statements apart: log⁡540\log_5 40log5​40 is the exact value, and 2.2922.2922.292 is a decimal approximation of it, close but not identical, which is exactly what ≈\approx≈ signals instead of ===.

Worked example 2 Solve 4⋅7x−1=3004 \cdot 7^{x-1} = 3004⋅7x−1=300

The power is buried under a coefficient, so isolate it first by dividing both sides by 444:

7x−1=75.7^{x-1} = 75.7x−1=75.

Now 757575 is not a whole-number power of 777, so match-the-bases is out. Take the common logarithm of both sides (legal, since both sides are positive) and use the power rule:

(x−1)log⁡7=log⁡75  ⟹  x−1=log⁡75log⁡7=log⁡775.(x - 1)\log 7 = \log 75 \;\Longrightarrow\; x - 1 = \frac{\log 75}{\log 7} = \log_7 75.(x−1)log7=log75⟹x−1=log7log75​=log7​75.

So the exact solution is x=1+log⁡775x = 1 + \log_7 75x=1+log7​75. For a decimal, use log⁡75≈1.87506\log 75 \approx 1.87506log75≈1.87506 and log⁡7≈0.84510\log 7 \approx 0.84510log7≈0.84510:

x≈1+1.875060.84510≈1+2.21875=3.21875.x \approx 1 + \frac{1.87506}{0.84510} \approx 1 + 2.21875 = 3.21875.x≈1+0.845101.87506​≈1+2.21875=3.21875.

Rounded to three decimal places, x≈3.219x \approx 3.219x≈3.219. As a sanity check, 72.219≈757^{2.219} \approx 7572.219≈75, and multiplying by 444 returns roughly 300300300.

Nothing here can create a false solution: every step (dividing by 444, taking a log of two positive quantities, dividing by log⁡7\log 7log7) is reversible.

Solving logarithmic equations

A logarithmic equation has the unknown inside a logarithm. Again there are two shapes.

Shape A: one logarithm equal to a constant. Rewrite log⁡bu=k\log_b u = klogb​u=k in exponential form, u=bku = b^ku=bk. This step is completely safe, and the reason is worth spelling out: bkb^kbk is positive no matter what kkk is. So any xxx satisfying u(x)=bku(x) = b^ku(x)=bk automatically satisfies u(x)>0u(x) > 0u(x)>0, which is exactly what the original equation needed. The candidate cannot fail the domain test. For example,

log⁡2(3x−1)=4  ⟹  3x−1=24=16  ⟹  x=173,\log_2(3x - 1) = 4 \;\Longrightarrow\; 3x - 1 = 2^4 = 16 \;\Longrightarrow\; x = \frac{17}{3},log2​(3x−1)=4⟹3x−1=24=16⟹x=317​,

and indeed 3x−1=16>03x - 1 = 16 > 03x−1=16>0, as guaranteed. You may check anyway, but this particular check cannot fail.

Shape B: one logarithm equal to another. By the theorem, log⁡bM=log⁡bN\log_b M = \log_b Nlogb​M=logb​N gives M=NM = NM=N. But the converse only holds when MMM is positive, so the equation M=NM = NM=N can carry solutions the original never had. Here the check is not optional. Take

log⁡3 ⁣(x2−6)=log⁡3x.\log_3\!\left(x^2 - 6\right) = \log_3 x.log3​(x2−6)=log3​x.

Equating the arguments gives x2−6=xx^2 - 6 = xx2−6=x, so x2−x−6=0x^2 - x - 6 = 0x2−x−6=0, so (x−3)(x+2)=0(x - 3)(x + 2) = 0(x−3)(x+2)=0, and the candidates are x=3x = 3x=3 and x=−2x = -2x=−2. Test them in the original equation. At x=3x = 3x=3 the arguments are 32−6=33^2 - 6 = 332−6=3 and 333, both positive, and both sides equal log⁡33=1\log_3 3 = 1log3​3=1. At x=−2x = -2x=−2 the right side is log⁡3(−2)\log_3(-2)log3​(−2), which does not exist, so x=−2x = -2x=−2 is not a solution at all. The only solution is x=3x = 3x=3.

Extraneous solutions, and where they come from

You met this mechanism in Solving Radical Equations. Squaring both sides is a one-way step: from u=vu = vu=v you may conclude u2=v2u^2 = v^2u2=v2, but u2=v2u^2 = v^2u2=v2 only gives back u=±vu = \pm vu=±v. Squaring destroys sign information, so the squared equation can hold at points where the original fails. The extra roots are not mistakes in your algebra; the step itself manufactured them.

Logarithms do the same thing, with the domain playing the role that the sign played. The product rule log⁡bM+log⁡bN=log⁡b(MN)\log_b M + \log_b N = \log_b(MN)logb​M+logb​N=logb​(MN) was proved for M>0M > 0M>0 and N>0N > 0N>0. If both are negative, the left side is meaningless while the right side is perfectly happy, since a product of two negatives is positive. Rewriting the left side as the right side can therefore enlarge the set of xxx where the equation makes sense, and that is exactly what happens below.

A combined equation can never lose a root: wherever the original sum of logs is defined, both arguments are positive, so the product rule turns one equation into the other and a genuine solution survives the rewrite. It can only ever add a root, and only at an xxx where both arguments have become negative, since that is the one way the product can be positive while the sum was never defined at all.

The paragraph above states the rule in words. The formal version replaces xxx‘s specific expressions with general ones, M(x)M(x)M(x) and N(x)N(x)N(x), and proves both directions from the domains alone. It is not needed to use the rule, only to see exactly why it always holds.

See the general proof

Equating arguments has the same one-way character, for the same reason: log⁡bM=log⁡bN\log_b M = \log_b Nlogb​M=logb​N gives M=NM = NM=N, but M=NM = NM=N hands back the log equation only when M>0M > 0M>0. Candidates from that step need the same test, as x=−2x = -2x=−2 discovered a moment ago.

Exponential equations are the honest contrast. Taking a log of both sides of 5x=405^x = 405x=40 is reversible because both sides there are already positive, and log⁡\loglog is one-to-one, so nothing is gained or lost. Whenever an exponential expression is isolated on one side and a positive number sits on the other, that same reasoning applies and the step never produces an extraneous root. It is the logarithmic side of this lesson that needs the domain check.

Worked example 3 Solve log⁡2x+log⁡2(x−2)=3\log_2 x + \log_2(x - 2) = 3log2​x+log2​(x−2)=3

Write down the domain before doing any algebra. The equation asks for log⁡2x\log_2 xlog2​x and log⁡2(x−2)\log_2(x-2)log2​(x−2), so it needs x>0x > 0x>0 and x−2>0x - 2 > 0x−2>0. Both conditions together say

x>2.x > 2.x>2.

Now combine the two logarithms with the product rule and convert to exponential form:

log⁡2 ⁣(x(x−2))=3  ⟹  x(x−2)=23=8.\log_2\!\big(x(x - 2)\big) = 3 \;\Longrightarrow\; x(x - 2) = 2^3 = 8.log2​(x(x−2))=3⟹x(x−2)=23=8.

That is a quadratic. Expand and factor:

x2−2x−8=0  ⟹  (x−4)(x+2)=0,x^2 - 2x - 8 = 0 \;\Longrightarrow\; (x - 4)(x + 2) = 0,x2−2x−8=0⟹(x−4)(x+2)=0,

so the candidates are x=4x = 4x=4 and x=−2x = -2x=−2.

Test each one in the original equation. For x=4x = 4x=4 the arguments are 4>04 > 04>0 and 4−2=2>04 - 2 = 2 > 04−2=2>0, and

log⁡24+log⁡22=2+1=3,\log_2 4 + \log_2 2 = 2 + 1 = 3,log2​4+log2​2=2+1=3,

so x=4x = 4x=4 is genuine. For x=−2x = -2x=−2 the first argument is −2-2−2, and log⁡2(−2)\log_2(-2)log2​(−2) does not exist, so x=−2x = -2x=−2 is rejected. It also fails the domain condition x>2x > 2x>2 that we wrote down at the start.

At x=−2x = -2x=−2 the two arguments are x=−2x = -2x=−2 and x−2=−4x - 2 = -4x−2=−4, both negative, and their product is (−2)(−4)=8(-2)(-4) = 8(−2)(−4)=8, precisely the value the combined equation wanted. The combined equation is satisfied there; the original one is not even defined there. The solution is x=4x = 4x=4.

Equations that hide a quadratic

Some exponential equations look unsolvable until you notice that one power is the square of another. Since 4x=(22)x=(2x)24^x = (2^2)^x = (2^x)^24x=(22)x=(2x)2, an equation containing both 4x4^x4x and 2x2^x2x is a quadratic wearing a disguise. Substitute u=2xu = 2^xu=2x, solve the quadratic, then undo the substitution.

Worked example 4 Solve 4x−3⋅2x−4=04^x - 3 \cdot 2^x - 4 = 04x−3⋅2x−4=0

Rewrite the first term so that both powers are built from 2x2^x2x:

4x=(22)x=22x=(2x)2.4^x = \left(2^2\right)^x = 2^{2x} = \left(2^x\right)^2.4x=(22)x=22x=(2x)2.

Let u=2xu = 2^xu=2x. The equation becomes an ordinary quadratic in uuu, which factors:

u2−3u−4=0  ⟹  (u−4)(u+1)=0  ⟹  u=4  or  u=−1.u^2 - 3u - 4 = 0 \;\Longrightarrow\; (u - 4)(u + 1) = 0 \;\Longrightarrow\; u = 4 \ \text{ or } \ u = -1.u2−3u−4=0⟹(u−4)(u+1)=0⟹u=4  or  u=−1.

Undo the substitution one root at a time. From u=4u = 4u=4 we get 2x=4=222^x = 4 = 2^22x=4=22, and equating exponents gives x=2x = 2x=2.

From u=−1u = -1u=−1 we get 2x=−12^x = -12x=−1, which has no solution: an exponential is positive for every real input, so 2x2^x2x never reaches −1-1−1. Notice this is a different situation from an extraneous root. A candidate xxx was never produced at all, because −1-1−1 is outside the range of 2x2^x2x; nothing needs to be rejected after the fact.

Check the survivor in the original equation:

42−3⋅22−4=16−12−4=0.4^2 - 3 \cdot 2^2 - 4 = 16 - 12 - 4 = 0.42−3⋅22−4=16−12−4=0.

The equation holds, so the solution is x=2x = 2x=2.

Common mistakes

Common mistakes

  • Skipping the domain test after combining logs. The combined equation is a consequence of the original, not an equivalent of it, so it can carry extra roots. Always test each candidate in the original equation, where every logarithm’s argument must be positive.
  • Rejecting negative candidates on sight. The test is whether each argument is positive, not whether xxx is. In log⁡2(x2−9)=4\log_2(x^2 - 9) = 4log2​(x2−9)=4 the value x=−5x = -5x=−5 is a perfectly good solution, since (−5)2−9=16>0(-5)^2 - 9 = 16 > 0(−5)2−9=16>0. Throwing it away because it is negative loses half the answer.
  • Inventing log⁡b(M+N)=log⁡bM+log⁡bN\log_b(M + N) = \log_b M + \log_b Nlogb​(M+N)=logb​M+logb​N. The product rule turns a sum of logs into the log of a product. There is no rule at all for the log of a sum.
  • Splitting a quotient of logs. log⁡40log⁡5\dfrac{\log 40}{\log 5}log5log40​ is not log⁡405=log⁡8\log\dfrac{40}{5} = \log 8log540​=log8. The first is about 2.2922.2922.292 and the second is about 0.9030.9030.903. Change of base produces a quotient of two logarithms, and it stays that way.
  • Equating exponents across different bases. From 3x=5x−13^x = 5^{x-1}3x=5x−1 you may not conclude x=x−1x = x - 1x=x−1. A shared base is the entire licence for dropping it, so with different bases you must take a logarithm instead.
  • Pulling a coefficient out of a logarithm. Writing log⁡(4⋅7x−1)=4log⁡7x−1\log(4 \cdot 7^{x-1}) = 4 \log 7^{x-1}log(4⋅7x−1)=4log7x−1 is wrong. Only an exponent comes out in front; a factor becomes a separate logarithm, so the correct expansion is log⁡4+(x−1)log⁡7\log 4 + (x - 1)\log 7log4+(x−1)log7. Taking a log before isolating the power is perfectly legal and reaches the same answer, but dividing by 444 first keeps the coefficient out of the way.
  • Trying to solve 2x=−82^x = -82x=−8. An exponential is always positive, so there is no solution and log⁡2(−8)\log_2(-8)log2​(−8) is not a number. Write “no solution” rather than a symbol that does not exist.

Key takeaways

  • For b>0b > 0b>0 with b≠1b \neq 1b=1, the exponential bxb^xbx and the logarithm log⁡b\log_blogb​ are one-to-one. So bu=bvb^u = b^vbu=bv exactly when u=vu = vu=v, and, for positive MMM and NNN, log⁡bM=log⁡bN\log_b M = \log_b Nlogb​M=logb​N exactly when M=NM = NM=N. Those two facts license every move in this lesson.
  • Exponential equation with a common base: rewrite both sides on that base and equate the exponents.
  • Exponential equation without one: isolate the exponential expression, take a logarithm of both sides, and use the power rule to bring the unknown down, then log⁡bM=log⁡Mlog⁡b\log_b M = \frac{\log M}{\log b}logb​M=logblogM​ for a decimal. The exponential side is automatically positive; once the other side is positive too, this step is reversible and no extraneous roots appear.
  • A single log equal to a constant: log⁡bu=k\log_b u = klogb​u=k becomes u=bku = b^ku=bk. Since bk>0b^k > 0bk>0, the candidate is automatically inside the domain, so this step cannot manufacture a root either.
  • Combining logs, or equating arguments, can enlarge the domain, so either move can manufacture roots. Solve the easy combined equation, then test every candidate in the original equation: each argument must be positive. This is the same one-way-step trap as squaring in a radical equation.
  • Since bx>0b^x > 0bx>0 for every xxx, a substitution value u≤0u \leq 0u≤0 yields no xxx at all. That is a root of the quadratic that produces no solution, which is not the same as an extraneous solution.
  • State rounded answers as rounded. The exact solution of 5x=405^x = 405x=40 is log⁡540\log_5 40log5​40; the number 2.2922.2922.292 is that solution to three decimal places.

The general proof that combining logarithms can add roots but never lose them

Combining logarithms can add roots, but never lose them#

Let M(x)M(x)M(x) and N(x)N(x)N(x) be expressions in xxx, and compare the equation you are given,

log⁡bM(x)+log⁡bN(x)=k,\log_b M(x) + \log_b N(x) = k,logb​M(x)+logb​N(x)=k,

with the equation you get after combining,

log⁡b ⁣(M(x) N(x))=k.\log_b\!\big(M(x)\,N(x)\big) = k.logb​(M(x)N(x))=k.

The first equation makes sense only where M(x)>0M(x) > 0M(x)>0 and N(x)>0N(x) > 0N(x)>0. The second makes sense wherever M(x)N(x)>0M(x)N(x) > 0M(x)N(x)>0, which happens when both factors are positive and also when both factors are negative. So the second equation’s domain contains the first equation’s domain, and it is strictly larger as soon as some xxx makes both factors negative.

Take any solution of the first equation. There M>0M > 0M>0 and N>0N > 0N>0, so the product rule applies and the left sides of the two equations are equal at that xxx; hence that xxx solves the second equation too. Combining cannot lose a root.

The reverse implication can only fail on the region where the domains differ. If xxx solves the second equation with M(x)<0M(x) < 0M(x)<0 and N(x)<0N(x) < 0N(x)<0, then the first equation is not even defined there, so xxx is not one of its solutions. Such an xxx is an extraneous root, produced by the step rather than by the problem. (Most of the added region causes no trouble at all, because nothing there solves the second equation either. The damage is done only by an added point that happens to be a root.)

That gives you a rule you can trust. Combine and solve, because the combined equation is the easy one. Then test every candidate in the original equation, where the test is simply whether each logarithm’s argument is positive. Keep the survivors and discard the rest.

∎

A bit of history (optional)

This lesson keeps telling you to throw an answer away, and the reason is always the same. A logarithm has been handed a negative number, and there is no such thing. Two of the best minds of their generation once spent a year arguing about that.

The quarrel ran by letter, through 1712 and 1713, between Gottfried Leibniz and Johann Bernoulli. Bernoulli had a proof that looked airtight, and it used the power rule you already know. Since (−1)2=12(-1)^{2} = 1^{2}(−1)2=12, taking logarithms of both sides gives 2log⁡(−1)=2log⁡12\log(-1) = 2\log 12log(−1)=2log1. So log⁡(−1)\log(-1)log(−1) has to be log⁡1\log 1log1, which is 000.

Leibniz refused it: a logarithm is an exponent, he wrote back. No exponent on a positive base ever gives a negative number, so there is nothing there to be 000. Neither man gave way, and the quarrel outlived them both.

It was settled a generation later, and Leibniz was right about the real numbers. Bernoulli’s step was the illegal one, because the power rule requires a positive argument. Applied to a negative one, it manufactures a value out of nothing.

That is the mechanism behind an extraneous root, in miniature. Folding two logarithms into one quietly widens the set of numbers your equation will accept. A candidate that survives the algebra may be standing on ground the original equation never covered. So put it back in and check what each logarithm is holding. Bernoulli did not.
