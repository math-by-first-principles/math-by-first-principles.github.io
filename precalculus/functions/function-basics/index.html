Functions and Function Notation

▾

Progress can't be saved in this browser, so this lesson's status can't be set.

Intuition

A taxi charges a fixed booking fee plus an amount for each kilometer. Once its pricing rule is settled, a distance determines a fare. But a list of rides from several companies might give two fares for the same distance. The difference is the information the input contains: does it determine one output?

Learning goals

  • Decide whether a relation gives exactly one output for each allowed input
  • Evaluate and interpret functions described by words, tables, graphs, and formulas
  • Select the correct branch when evaluating a piecewise function
  • Calculate average rates of change and explain their signs and units
  • Distinguish an interval's average rate from what happens inside that interval

What makes a relationship a function?

Suppose one taxi charges 444 dollars plus 222 dollars per kilometer, with no other charges. For a trip of 333 kilometers, the fare is 4+2(3)=104+2(3)=104+2(3)=10 dollars. That distance cannot give a second fare under the same rule.

A function assigns exactly one output to each allowed input. The domain is the set of allowed inputs; the range is the set of outputs actually produced. For the taxi model, the input is a nonnegative distance and the output is its fare. A relation is a collection of input-output pairings; some relations satisfy the function requirement and some do not.

If a record instead pairs distance 333 with both 101010 dollars and 131313 dollars, fare is not a function of distance alone in that record. There may be a missing detail, such as the company. A disagreement with the function requirement does not make the observations impossible; it tells us the chosen input is insufficient.

Different inputs may share an output. The left diagram below still defines a function because each input has one outgoing arrow. The right one fails because input 111 has two different outputs.

One relationship, several representations

Function notation names a function and the input being used. Write the taxi rule as

C(d)=4+2d.C(d)=4+2d.C(d)=4+2d.

Read C(d)C(d)C(d) as “C of d”: the fare when the distance is ddd. It does not mean CCC multiplied by ddd. Here ddd is the independent quantity, the input selected for the model. The fare C(d)C(d)C(d) is the dependent quantity, whose value the rule determines. This language describes the model’s roles, not a claim that one quantity always causes another in the real world.

2d=18,d=9.2d=18,\qquad d=9.2d=18,d=9.

Reading a graph as a function

A graph uses horizontal position for the input and vertical position for the output. In the next relation, input 333 reaches heights 111 and 555. That one conflict is enough to show the relation is not a function of xxx.

This gives the vertical-line test: a graph represents yyy as a function of xxx exactly when every vertical line meets it at most once. A vertical line keeps the input fixed, so two intersection points would assign two outputs to one input. A line that misses the graph simply passes through an input outside the domain.

A horizontal graph passes this test. Many inputs can have the same output, and a vertical line still meets that graph only once. A vertical graph fails because one input has many outputs.

Choosing a piecewise rule

A single function can use different formulas for different inputs. The condition beside a formula tells you when to use it.

Consider the piecewise function

p(x)={x+3,x<2,2x+3,x≥2.p(x)=\begin{cases} x+3,&x<2,\\ 2x+3,&x\ge2. \end{cases}p(x)={x+3,2x+3,​x<2,x≥2.​

For input 111, use the first branch because 1<21<21<2, giving p(1)=4p(1)=4p(1)=4. For input 333, use the second branch because 3≥23\ge23≥2, giving p(3)=9p(3)=9p(3)=9. Choose the branch using the input, before calculating its output.

Worked example 2 Include the boundary exactly once

Problem. The function ppp is defined by

p(x)={x+3,x<2,2x+3,x≥2.p(x)=\begin{cases} x+3,&x<2,\\ 2x+3,&x\ge2. \end{cases}p(x)={x+3,2x+3,​x<2,x≥2.​

Case A: Find p(−4)p(-4)p(−4).

Case B: Find p(2)p(2)p(2).

Case C: Find every input for which p(x)=7p(x)=7p(x)=7.

Solution. Case A: Since −4<2-4<2−4<2, use x+3x+3x+3:

p(−4)=−4+3=−1.p(-4)=-4+3=-1.p(−4)=−4+3=−1.

Case B: Since 2≥22\ge22≥2, use 2x+32x+32x+3:

p(2)=2(2)+3=7.p(2)=2(2)+3=7.p(2)=2(2)+3=7.

Case C: In the first branch, x+3=7x+3=7x+3=7 gives x=4x=4x=4. But 4<24<24<2 is false, so this candidate is not valid for that branch.

In the second branch, 2x+3=72x+3=72x+3=7 gives x=2x=2x=2. This satisfies x≥2x\ge2x≥2, so the only input is 222.

For every declared input, a piecewise rule must assign one output. A gap between the conditions leaves an input undefined. Overlapping conditions that give different outputs create a conflict. We usually write disjoint conditions, as above, to make the choice clear.

Measuring change over an interval

Function values answer “how much?” A rate compares the change in output with the change in input.

For the taxi, the fare rises from 888 to 121212 dollars as distance rises from 222 to 444 kilometers. The change is 444 dollars over 222 kilometers, or 222 dollars per kilometer. Subtract before dividing; the ratio 12/412/412/4 includes the booking fee and answers a different question.

The average rate of change from input aaa to a different input bbb is

f(b)−f(a)b−a.\frac{f(b)-f(a)}{b-a}.b−af(b)−f(a)​.

The numerator is output change and the denominator is input change. Use the same order in both. Its units are output units per input unit. On a graph, this ratio is the slope of the secant line, the straight line through the two endpoint points. It summarizes the change between those endpoints, even if the graph between them is curved.

Worked example 3 Read the rate and its units

Problem. A marked point has height h(t)=t2+1h(t)=t^2+1h(t)=t2+1 centimeters at time ttt seconds, for 0≤t≤40\le t\le40≤t≤4.

Part A: Find its average rate of height change from one second to four seconds.

Part B: Interpret the result.

Part C: Find the rate from one second to two seconds and compare the two rates.

Solution. Part A: First calculate the endpoint heights:

h(1)=2,h(4)=17.h(1)=2,\qquad h(4)=17.h(1)=2,h(4)=17.

The height increases by 151515 centimeters over 333 seconds:

17−24−1=5.\frac{17-2}{4-1}=5.4−117−2​=5.

The average rate is 555 centimeters per second.

Part B: This is the rate a constant increase would need to produce the same total height change over those three seconds.

Part C: For the shorter interval, h(2)=5h(2)=5h(2)=5, so

5−22−1=3.\frac{5-2}{2-1}=3.2−15−2​=3.

That average rate is 333 centimeters per second. The two rates differ, so the height is not changing at a constant rate throughout the full interval.

When the later output is lower, the rate is negative. A container whose water volume drops from 303030 to 181818 liters between minutes 222 and 666 has average rate (18−30)/(6−2)=−3(18-30)/(6-2)=-3(18−30)/(6−2)=−3 liters per minute. The sign describes a net decrease; it is not a negative amount of water.

What an average does not tell you

Two endpoints can match even when the function changes in between.

Worked example 4 Zero net change does not mean no change

Problem. A function rrr has values r(0)=6r(0)=6r(0)=6, r(2)=10r(2)=10r(2)=10, and r(5)=6r(5)=6r(5)=6.

Part A: Find the average rate from input 000 to input 555.

Part B: Decide whether these data show a constant function on that interval.

Solution. Part A: The beginning and ending outputs are equal:

r(5)−r(0)5−0=6−65=0.\frac{r(5)-r(0)}{5-0}=\frac{6-6}{5}=0.5−0r(5)−r(0)​=56−6​=0.

The average rate is zero.

Part B: The middle value is 101010, which differs from 666, so the function is not constant. The overall average describes the net change, not every change inside the interval.

Likewise, a table can show equal average rates on several intervals without establishing a constant rate between all its entries. A stated linear rule justifies that stronger conclusion; a finite list of measurements does not by itself.

A function has f(1)=9f(1)=9f(1)=9 and f(7)=9f(7)=9f(7)=9. Which statement must be true?

Answer choices

The endpoint difference is zero, so the average rate is (9−9)/(7−1)=0(9-9)/(7-1)=0(9−9)/(7−1)=0. The given values say nothing about the intervening outputs.

Common mistakes

Common mistakes

  • Repeated outputs: two inputs may share an output. Check for two different outputs assigned to one input.
  • Function notation: f(3)f(3)f(3) is an output at input 333, not multiplication and not the equation f(x)=3f(x)=3f(x)=3.
  • Piecewise boundaries: select the branch from its input condition and check that any solved input belongs to that branch.
  • Average rates: divide output change by input change, keeping subtraction order and units consistent.
  • Endpoint evidence: zero average change does not establish a constant function, and a short table does not determine every intervening value.

Key takeaways

  • A function gives exactly one output for each allowed input; its domain records those inputs.
  • Representations describe the same pairings in different ways. Read the input and output roles before calculating.
  • A piecewise rule uses its conditions to select a formula; every allowed input still needs one output.
  • An average rate is output change divided by input change, with output units per input unit.
  • An average compares endpoints. Use additional information to describe what happens between them.

A bit of history (optional)

The familiar parentheses in f(x)f(x)f(x) were once a new idea. In work dated 1734, the Swiss mathematician Leonhard Euler used a letter with a parenthesized argument to denote an unspecified function. His paper appeared in print in 1740. The notation let him refer to a relationship without first spelling out a particular formula for it.

The form was not inevitable. Leibniz had used a mark above the inputs, and Euler later tried placing a colon between a function’s letter and its inputs. The familiar parentheses endured, while the modern language of a mapping between sets developed much later. A notation could remain useful even as mathematicians changed what they allowed it to describe.
